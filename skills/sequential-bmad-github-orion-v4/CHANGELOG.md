## v5.1 — Orchestrator-owned CI/merge + targeted-test finalize + issue pre-flight triage + sub-agent git/probe hardening

Edited in place on the `-v4` folder (not forked) by explicit user choice — these are corrections derived from three later production-run lessons-learned logs (the runs that exercised v3/v4). Nine improvements, walked one-by-one and filtered to the high-value set; seven lower-value candidates were dropped (Phase-0 guard allowlist, warm `node_modules` seeding, Edit-tool smart-quote guard, QA scratch cosmetics, perf knobs 4b/4d/4e, and stack-specific engineering hazards — the last belong in the *application* repo's own conventions, not a distributable skill).

- **Agent D stops at PR-open; the orchestrator owns the CI-watch + hard pre-merge gate + squash-merge.** The single most recurring failure across runs: the Sonnet finalize agent repeatedly reached for a background `Monitor`/wait tool to await CI and ended its turn non-terminally (no contract line), even after the prompt was explicitly hardened against it — so the fix removes the *reason* to wait rather than re-prompting. Agent D's terminal value is now `agent-status: pr-opened pr:<N>` (no more `merge-sha` line); the old steps 8/8b/9/10/11 (wait-CI, hard pre-merge gate, merge) moved into a new SKILL §1.4 "Orchestrator-owned CI-watch + hard pre-merge gate + merge" subsection that runs foreground with synchronous `gh` polling. Red CI → infra-flake rerun or re-dispatch (recovery agent / focused Agent-D fix turn), bounded at 5 cycles. The §1.5 post-merge audit is kept as the backstop. Touch points: pipeline table (Agent D row), Core Principle #1, §1.4 Agent-D dispatch + the new gate subsection, §1.5 trigger + revert-path wording, checkpoint list, Cleanup checklist, Failure-handling table, shared-boilerplate return contract, `agent-d-finalize.md` (job intro + steps 7–8 + return summary + final line), README Phase-1 description.
- **CI empty-rollup race fixed: settle-and-repoll before any no-CI fallback.** An empty `statusCheckRollup` right after `gh pr create` is almost always a registration race, not an absence of CI. The orchestrator gate now re-polls for a ≥90–120s settle window (4–6 reads ~20–30s apart) AND cross-checks `gh run list --branch <head>`; it treats the rollup as genuinely empty (→ local-build gate) ONLY if it stays empty across the window AND zero runs are reported. Prevents merging before CI even registers.
- **Finalize runs targeted tests + a full compile locally, not the full suite.** The full backend+frontend suite previously ran three times per issue (locally in finalize, again in CI which finalize then waited on, then once more at batch-QA Gate 1) — the biggest wall-time cost. Agent D step 2 now runs a full COMPILE + only the test projects whose source the diff touches; CI is the authoritative full-suite gate (enforced by the orchestrator gate), and the full LOCAL suite runs only as the genuine-no-CI fallback (the orchestrator runs it). Batch-QA Gate 1 (full suite on the integrated tip) is untouched. The baseline-vs-regression check is kept but applied to targeted failures.
- **Issue pre-flight triage (one gate, three parts).** (a) **Code-grounding** — Agent A's old bug-only precheck is generalized: ALL issues have their load-bearing claims (file paths, "dead code"/"already defined", stated root cause, scope counts) verified against live code before the story is written, with a "Grounding corrections" table baked in so B/C/D don't re-trust a stale issue body. (b) **No-op / overtaken-by-events short-circuit** — Agent A returns `expected-diff: none — <evidence>` when the work already shipped; the orchestrator (§1.4) independently grep-confirms and pauses for a close-as-resolved vs keep-open decision instead of burning a dev→review→finalize cycle. (c) **Human-gate readiness** — new Phase 0 step 5b-r scans issue bodies for unlifted gate banners (blocked / approach-decision-needed / confirm-before-starting), distinguishes them from lifted `✅ DECISION MADE` ones, and defaults to excluding the still-gated issues (user can override).
- **Hardened terminal-line contract + mandatory on-disk verification.** Shared boilerplate gains a verbatim copy-paste terminal-line example (incl. Agent D's new `pr-opened` form); each per-issue agent gets a hard "your VERY LAST line must be exactly …" reminder immediately before its return block. §1.4 inferred-terminal-proceed now REQUIRES an on-disk artifact check (story file non-empty / `git diff` non-empty / PR exists) before proceeding when `SendMessage` is unavailable — it routes to §1.7 if the artifact is absent, so the fallback can't be reached more easily than a real contract line.
- **Probe-mutation isolation: never `git stash` in sub-agents.** The stash stack is a repo-GLOBAL ref shared across all worktrees, so a sub-agent stash can corrupt another tree — the actual hazard behind the prior "no git stash" guidance. Codified in the shared boilerplate (both per-issue and batch-QA), AND the two places v4 still used stash are replaced: Agent D's baseline check now uses a throwaway detached worktree at the batch tip, and the §1.4 crash-retry "Before Agent B" preserves the story file via a scratch-folder backup instead of stash. Also bans `sed -i` on tracked files (CRLF→LF leak).
- **Worktree & cwd discipline.** Both boilerplates now state that the harness cwd + search/edit/MCP tools default to the MAIN checkout, not the worktree — agents must pass absolute worktree paths and verify artifacts land in the worktree (and MCP screenshots get moved out of the repo) so grounding greps hit the right tree and nothing leaks into the PR.
- **Finalize git discipline.** Agent D gains explicit precise-staging (never `git add -A`; compare `git status` against the expected file list) and a `git check-ignore -v` step before including framework/output artifacts. The auto-close keyword audit (already present) gains a portability note: use `grep -iE`, never `grep -P` (the bundled Windows/Git-Bash grep has no Perl regex and false-negatives the audit), and a Node/JS regex for Unicode classes.
- **Batch→base rebase recipe.** The pr-author's additive-conflict resolution gains `GIT_EDITOR=true git rebase --continue` (avoids an editor hang; `--no-edit` doesn't exist for rebase) and an explicit "keep both sides' added imports / union members" example.

Stats-report footer version bumped to `v5.1`.

## v5.0 — New skill version (`-v4`): run from any base branch + TODOs to lessons-learned + neutral exhaustive QA report

Forked from `sequential-bmad-github-orion-v3` (which was renamed to `sequential-bmad-github-orion-v3-old` and frozen, by explicit user choice, so an attempt to run the old name surfaces the `-old` deprecation marker and nudges toward this version). Three user-requested improvements from real-run feedback:

- **Run from any base branch (not just `main`).** The orchestrator now captures a `<base-branch>` at Phase 0 = the branch it was invoked from (`git rev-parse --abbrev-ref HEAD`), and the batch forks from / the Draft PR targets / Phase 4 verifies against that branch instead of the hard-coded default branch. This lets the user run a batch from a feature/integration branch (or a separate worktree) and keep working on `main` untouched. Running from `main` reproduces the prior behavior exactly (backward-compatible). Phase 0 step 2 no longer requires the default branch — it only requires a *named* branch (detached HEAD halts) and publishes a local-only base branch to `origin` (step 4) so GitHub can host the batch→base-branch Draft PR. New `<default-branch>` placeholder retained for the few spots the repo's actual default still matters (auto-close-keyword propagation, stats-report project-context query). Touch points: frontmatter + orchestrator intro, Core Principles #1/#3, Phase 0 steps 2/4/9, §1.1/§1.5 excursion note, Phase 4.1, §2.2b Draft-PR target, the `pr-author` (`--base <base-branch>`, conflict-rebase onto `origin/<base-branch>`, DO-NOT-MERGE fallback), Agent D's per-issue-PR target wording, "Stay on the base branch" implementation note, Failure-handling hard-halt list, "does NOT do" (now explicitly: does not touch the default branch when the base branch is something else), and the manifest. New log event `base-branch-published`; `merge-sha-not-found-on-main` → `merge-sha-not-found-on-base`.
- **TODOs left during development are recorded in lessons-learned (don't-forget-the-gap channel).** The pipeline already *surfaced* markers (Agent C step 5b review note → Agent D PR body → `annotations[]` → qa-report). It now ALSO writes a durable ⚠️ lessons-learned finding the moment markers are introduced, naming each `<file>:<line>`, what was deferred, and why — so a left-behind feature/gap can't be forgotten after the run. New Agent C step 5b(d) is the primary enforcement point (its diff scan catches markers from any per-issue agent); both shared boilerplates' lessons-learned contracts and Core Principle #1 now state that a left/observed TODO always warrants a finding.
- **The QA report is now a NEUTRAL, EXHAUSTIVE test plan — not a "we're green" artifact.** Real-run feedback was that the `pr-author`-written `qa-report.html` read too positively for a downstream full-round QA agent to work against. New "Tone & neutrality" mandate at the top of the report section: it is a TEST PLAN for an independent QA agent, claims are phrased as things to *verify* (never asserted as proven), automated gates passing ≠ feature correct, and uncertainty is surfaced loudly. The cover gains a neutrality disclaimer + a factual gate-results line + a "What automation did NOT cover" callout; the status pills are relabeled "AUTOMATED GATES GREEN — QA NOT YET DONE" so they read as gate outcomes, not QA verdicts. Per-story Part 2 gains four corner-coverage angles — **Error & failure states**, **Empty / loading / boundary states**, **Persistence & state across navigation** — plus two always-present sections: **Risks — most likely to be broken** (where the QA agent should be most skeptical) and **What automation did NOT cover** (honest gap map). Grounded by a new `coverage-caveats` field in the `test-and-fix` → `pr-author` handoff (the gate agent reports what it did NOT actually exercise; environmental escapes and UI-unreached/backend-only stories flow into it). The Intro is reframed factual/neutral.

## v4.1 — Fix-in-place-first gate: stop over-deferring work that could ship in the current PR

Motivating finding: v4.0 built rich machinery for *tracking* deferrals (Core Principle #9 — file-and-link a `#N`, dedupe, pre-close check, scope-ledger) but never defined a rule for *whether* something should defer at all. The only implicit boundary was binary scope ("in the story's ACs or not"), so any finding a hair outside the ACs fell into the frictionless deferral funnel — even small, safe fixes the agent was already positioned to make. This release adds the missing counterweight. Edited in place on `-v3` (not forked) by explicit user choice.

- **New Core Principle #10 — fix-in-place-first; defer is the fallback, not the default.** Defines the reusable **cheap-and-safe test**: a finding is fixed NOW in the current PR when it is *small · local · covered by tests already running · low blast-radius · scope-neutral*; it defers (and is then tracked per #9) only when it FAILS the test. "It wasn't in the story's ACs" is explicitly NOT a sufficient reason to defer. Each deferral names the single criterion it failed, so the choice is auditable; ties break toward defer (safety). Principle #9 now points at #10 ("apply #10 first").
- **Agent C (code-review) step 6b** — adjacent findings (just outside the diff / ACs) run the gate: pass → apply an "🛠 Opportunistic fix (in-scope per CP#10)" beyond the original diff; fail → tracked deferral naming the failing criterion. Step 8 no longer returns `incomplete` for a non-blocking adjacent finding — it records a deferral and continues. Return summary gains **Opportunistic fixes applied** and **Findings deferred** (with failing criterion) fields.
- **Agent B (dev-story) step 5b** — opportunistic in-place fixes for small/safe defects crossed while implementing, governed by the same gate; failures recorded as deferred checks in the handoff. Explicitly NOT a license to hunt unrelated work.
- **Batch-QA `test-and-fix`** — new "EVERYTHING ELSE: FIX-IN-PLACE-FIRST" section after the hard SCOPE EXCLUSIONS: anything not in the three hard-exclusion blocks is subject to the gate; prefer fixing over handing the pr-author a deferral.

## v4.0 — New skill version (`-v3`): close the deferral scope-leak + hard CI-green merge gate + human-like QA

Forked from `sequential-bmad-github-orion-v2` (kept as-is per the versioning convention). The motivating finding: the pipeline already *detected* deferred work (pre-existing baseline failures, carry-forward gaps, TODOs) but never *filed or linked* it, so "out of scope" prose reached PR bodies with no tracking `#N` and quietly leaked. Plus two operational gaps surfaced from real runs.

- **Renamed** the skill `sequential-bmad-github-orion-v2` → `sequential-bmad-github-orion-v3` (frontmatter, headings, finalize-mode invocation, stats-report footer, batch-PR provenance line, README/usage). Historical CHANGELOG entries below keep their original version names.
- **New Core Principle #9 — every deferral leaves a tracked `#N`.** Detection without filing is how work leaks; the pipeline now files-and-links.
- **Delta A — file & dedupe deferral annotations (the leak fix).** New Phase 2.1 step (h) builds a whole-batch, deduped `<deferral-filing-block>` (baseline-failure by `test_file`, carry-forward by normalized `gap`) that carries each item's observing issues **and their per-issue PR numbers**. The `pr-author` (2.2b), before writing the report or opening the Draft PR, **finds-or-reuses ONE tracking issue per distinct deferral** (searches open issues first — never duplicates per run; labels `baseline-failure` / `recovered-scope`) and **writes the resulting `#N` back into every per-issue PR body** under a structured `## Out of scope / Follow-ups (tracked)` section, plus a batch-level mirror in the Draft PR body. **Hard rule:** the `pr-author` never emits an "out of scope" / "pre-existing baseline failures" / "follow-up" line without a trailing `#N`. New run-level register `filed_deferrals[]` (from the `pr-author`'s `deferrals-filed` return block). Agent D now notes that its baseline-failure PR-body lines are intentionally left unlinked at Phase 1 for the `pr-author` to back-link.
- **Delta B — pre-close link check (Phase 4.2).** Before closing each batched issue, the orchestrator re-scans that issue's per-issue PR body (and the merged batch PR body) for unlinked deferral lines; any found are filed/linked (find-or-reuse) before the close. New log event `deferral-linked-before-close` / `pre-close-link-check-clean`. Covers finalize-mode re-invocations where the Phase-2 register was lost.
- **Delta C — scope-ledger panel in the stats report (Phase 4.3).** New section 8: per annotation kind, Detected · Tracked (`#N`) · Created · Reused · Unlinked. Unlinked code-work deferrals render red when > 0 (target: 0); TODOs render as "surfaced for triage".
- **Delta D — hard CI-green gate before any per-issue PR merges into the batch.** Motivated by a real incident where a PR with failing CI was merged into the batch. Agent D gains step 8b: an authoritative pre-merge reading (`gh pr view --json mergeable,mergeStateStatus,statusCheckRollup`); no `--admin`/override. Because the pipeline cannot rely on GitHub branch protection / required-check enforcement (the runner may lack admin access), this gate IS the enforcement — so it treats **every** check in `statusCheckRollup` as merge-gating, not only the ones GitHub marks "required" (a "required-only" reading would gate on nothing). When the rollup is **empty** (no workflow fired for the PR's changed paths) it does NOT pass vacuously: Agent D re-runs the same full build + test from step 2 in the worktree and requires it green as the merge evidence. Backstopped by an orchestrator §1.5 post-merge CI audit that mirrors the same logic (every present check green; an empty rollup certified only by the local-build evidence, never waved through) and reverts the squash off the batch + routes to §1.7 on a gate miss. Core Principle #1 updated; new log events `pre-merge-ci-gate-pass` (remote-checks case), `pre-merge-local-gate-pass` (empty-rollup local-build case), `post-merge-ci-audit-clean`, `red-ci-merge-detected`.
- **QA like a human user, not a computer** (Gate 3 `test-and-fix` + the `pr-author` report's click-paths). Reach features by navigating the real UI from the landing page — not by deep-linking to known URLs or pre-seeding state via the API (except when the deep-link/endpoint is itself under test). An unreachable-by-clicking feature is a finding; this surfaces the broken-nav / dead-button / wrong-href / role-gating bugs a real user would hit.
- **Run-log checkpoints + Failure-handling table + Cleanup checklist** updated for all of the above.

## v2.5 — anti-halt autonomy + production-ready-code framing + downstream-agent QA report

Changes vs v2.4:

- **Core Principle #1: Production-ready code is the success bar.** Front-matter description + new top-of-list Core Principle. Every other principle now formally serves this bar. Operational definition includes: all tests + e2e green, live-stack QA green, zero regressions, no `Closes #N` leakage, no stubbed/half-implemented surfaces, TODO/FIXME/HACK markers surfaced to user, project conventions adhered to, clean Conventional-Commits history. Existing principles 1-7 shifted to 2-8.
- **Anti-halt autonomy (Core Principle #6 rewrite).** The orchestrator no longer halts mid-queue. New §1.7 "Per-issue failure procedure (skip-and-continue with revert)" defines the full recovery flow: heavy retry → dedicated Opus recovery sub-agent → on persistent failure, revert any partial commits off the batch branch, mark the issue FAILED in a new `failed_issues[]` register, post 🚧 failure comment + write `<session-folder>/failures/<N>-<slug>/` (diagnosis.md + last-state.diff + agent-transcripts/), clean up worktree (story branch RETAINED on origin for manual investigation), surface a one-line chat notice, continue to next issue. Batch branch stays in a known-green state at all times. (Superseded in v3.0 by the halt-and-converse model.)
- **Failure flagging — 4 always-on + 4 end-of-run surfaces.** Every failure surfaces via: (1) GitHub issue 🚧 comment, (2) real-time chat notice to the user, (3) `<session-folder>/failures/<N>-<slug>/` folder with full record, (4) `run.jsonl` event. At end-of-run: (5) Phase 1 queue-end summary printed before batch-QA spawn, (6) Phase 2 qa-report.html's mandatory "Failed issues" slide, (7) Draft batch PR body's top-of-body `⚠️ Failed issues` callout, (8) `manifest.md` with one of five `Status:` values (`succeeded` / `succeeded-with-failures` / `succeeded-with-qa-failure` / `abandoned` / `halted`) plus a "Failed issues" summary section.
- **Hard halts narrowed to two.** Only Phase 0 precondition failures and explicit user "stop" mid-loop halt the skill. Everything else (logical incomplete, terminal-line unrecoverable, runtime crashes, merge conflicts, Gate 1/2/3 unresolvable, batch-QA failed) is a soft failure.
- **Phase 2 conflict-resolution expanded from one 4-gate strategy to three strategies (A → B → C).** (Superseded in v3.0: Strategies B and C removed; Strategy A kept; pause-and-converse for everything else.)
- **Phase 2 Gate retry budget bumped 5 → 10 cycles**, with targeted-revert-via-§1.7 fallback when 10 cycles can't make a gate green. (Superseded in v3.0: budget reduced back to 3 cycles.) Batch-QA failure now opens a Draft PR with a top-of-body `❌ DO NOT MERGE — automated batch QA failed` callout (full reason + qa-report.html link) instead of halting; Phase 3 long-poll still scheduled so the human can resolve manually or close.
- **Crash retry budget bumped 1 → 2 retries per agent slot.** Third crash on the same slot routes to §1.7 instead of halting.
- **Agent D return classification — CI infra-flake auto-rerun.** Agent D `incomplete` reasons are now classified: infra-flake patterns (`setup-bun`/`setup-node`/`setup-dotnet` 401/503, `Failed to fetch url`, `Bad credentials`, `ECONNRESET`) trigger one `gh run rerun --failed` before consuming the recovery path. Real code red goes through recovery agent → §1.7.
- **Agent B no-commit verification.** Orchestrator runs `git log origin/<batch-branch>..HEAD` to verify zero commits when Agent B returns. (Superseded in v3.0: removed in favor of Agent D step 4b as the single audit point.)
- **Agent D pre-push auto-close keyword audit (step 4b — most critical pre-push check).** Before the first push, Agent D MUST scan EVERY unmerged commit via `git log origin/<batch-branch>..HEAD` + per-commit `git show --no-patch --format=%B`, grepping each message for the regex `\b(close[sd]?|fix(es|ed)?|resolve[sd]?)\s+#[0-9]+`. On match: amend (if HEAD) or non-interactive rebase/filter-repo rewrite (if older) to replace every auto-close keyword with `Refs`. Re-grep to confirm clean. (In v3.0 this became the SINGLE audit point.)
- **SendMessage availability probe + inferred-terminal-proceed.** Terminal-line recovery now probes whether `SendMessage` is callable in this harness. If yes, use it. If no (and all three gates hold), apply inferred-terminal-proceed: treat the agent's terminal state as inferred from the parsed summary, log + post audit notice, continue.
- **Failure handling section rewritten.** New tabular layout: 2 hard halts vs N soft-failure paths. Five `Status:` values for `manifest.md`. Cleanup checklist updated.
