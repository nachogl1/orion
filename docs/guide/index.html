From a first conversation to finished, checked software.

orion is a framework you install into your own project. It gives Claude Code ready-made skills and one shared set of working rules, so the assistant plans, builds, reviews and checks work the same careful way for everyone on the team.

Install

Up and running in four steps

orion is installed into a project, never for your whole computer. Once it is in, whoever clones the project gets it too: there is nothing for teammates to set up.

  1. Have two things ready

    • Git, the tool that downloads and tracks code. On Windows, install Git for Windows.
    • Claude Code, the AI assistant itself. Follow the Claude Code setup guide and open it once inside your project.

  2. Run one line in your project folder

    Open a terminal in the project folder and paste the line for your system. It fetches the latest orion, puts it into the project and tells you what it added.

    curl -fsSL https://raw.githubusercontent.com/nachogl1/orion/main/orion.sh | bash -s -- init
    irm https://raw.githubusercontent.com/nachogl1/orion/main/orion.ps1 | iex
    • Want the optional status bar? Add --statusline to the end of the Mac/Linux line, or answer yes when the installer asks.
    • Want updates applied without being asked? Choose auto when the installer asks, or add --update-mode auto.

  3. Open Claude Code and run the check first

    Run /orion-verify before your first commit (the first session also asks for it). It checks that everything fits together: your project's CLAUDE.md, the rules it now imports, the skills (orion's and any you already had) and the settings. It repairs what is mechanical, and asks before changing anything that is yours: filling in the build and test commands it finds in your project, moving a folder the rules expect somewhere else (your PRDs, say), and un-ignoring orion's files if your .gitignore would keep them from your team. Repeat it any time.

  4. Commit what it added

    Save the new files to the project like any other change, so your teammates get orion with their next pull.

Prefer to let the assistant do it? Open Claude Code in your project and say "set up orion in this project".
Use it with care. orion tells an AI assistant how to work in your project, and the assistant will run commands and edit files on your machine. Review what you install, keep your work saved, and use it at your own risk. It is under constant improvement and is provided as-is.
What you get

What orion installs, and how each part is updated

Four parts. Three live in the project and reach your teammates with a clone; one lives only on your computer. orion has one version number, raised each time something a project receives changes.

The base rules

Where: .claude/orion/BASE_CLAUDE.md, imported by your CLAUDE.md. Owner: orion; never edit the copy. Updates: replaced on every update. When they change, the next session offers /orion-verify once, to check they still fit your project.

The skills

Where: .claude/skills/<name>/, each marked with an .orion-managed file. Owner: orion; your own skills (no marker) are never touched. Updates: replaced on every update.

Your personal rules

Where: offered for your own ~/.claude/CLAUDE.md, on this computer only. Owner: you. Updates: each rule orion offers carries the orion version number that last changed it, and your file's ORION GLOBAL heading records the version you last went through. A rule from a higher version is offered, at most once a day; nothing is written without your yes.

The status bar (optional)

Where: ~/.claude/statusline, on this computer only; the project carries orion's copy. Owner: you. Updates: it records the orion version number of the copy it came from. When the project brings one from a higher version, the session start offers it: an unedited copy is replaced, an edited one gets orion's changes merged in, and you can skip that version.

After install

Staying up to date

Nothing changes without your say-so. The update mode and the tidy-up limits live in .claude/orion/config.json.

Updates

Every session start compares the orion version number your project has with the newest release, and offers an update only when there is a higher one; "Not now" keeps it quiet until the next release. updateMode decides what happens: ask (the default), auto or off. Say yes, then commit the result as usual.

Your personal rules

At most once a day, orion offers rules for your own ~/.claude/CLAUDE.md. You accept, skip or reword each one; nothing is written without your yes, and the rest of your file is never touched.

A tidy repository

Once the project reaches branchLimit or worktreeLimit (20 each by default), the session start offers /clear-git-resources. Set them higher, or to off.
