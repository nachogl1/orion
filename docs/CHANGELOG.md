# Changelog

Newest first. One line per pull request: what changed and why it matters to someone using orion.

- The status line is never updated without its owner's word, even under `updateMode: auto`: a newer one is offered at session start, and an unedited copy is replaced only when the person says yes, so nobody's status bar changes behind their back.
- The status line now follows orion updates: every project carries orion's copy, an unedited copy on each computer picks up a newer one at the next session start, and an edited one is merged in (`orion.sh statusline merge`, edits kept) or declined (`statusline skip`) on its owner's word, so a status line change reaches every developer.
- Agents now offer `/dev-quick` for every code change asked for in chat, and a yes ships it end to end with no further questions: a clear request skips the interview and the draft look, and the skill can be started by the agent, not only by typing it.
- `BASE_CLAUDE.md` and the starter `CLAUDE.md` no longer suggest an example boundary: each project writes its own boundaries, if it has any.
- Small fixes to `BASE_CLAUDE.md` (TLDR after any problem, `fix/` branches allowed, the AI-model rule only for projects that call a model, a neutral boundary example), and the `-vN` skill-versioning rule is gone: every skill is edited in place.
- The commit-email rule and its CI check are gone: emails in commits are allowed again, so pull requests merge with GitHub's normal squash merge.
- A clash between a person's own rules file and BASE_CLAUDE.md is now fixed for good: with the person present the assistant offers to change one file or the other; an unattended run never stops to ask, follows the baseline and logs the clash as friction in its run report.
- BASE_CLAUDE.md gains the reply rules that help every project: accuracy beats brevity beats shape, a reply shaped to its job (report, decision, answer), full plain sentences, a status line while work runs, and pull requests named by their issue.
- New `docs/PRDs/PRD.md` describes orion as it is today (users, vocabulary, scope, do-not-build list, acceptance bar, build decisions), so the rule that the PRD is the north star holds for orion itself; a draft until the owner approves it.
- Utility skills: one BOM-free write method, no pointers into the orion repo, a `VERIFY.md` for `generate-project-writeup`, and the sweep never treats a QA worktree as safe
- An auto-update at session start now time-limits only the download, never the copy, so a slow Windows machine can no longer be left with a half-updated orion; the hook's time limit goes from 20 s to 60 s, and existing installs are raised by their next `update` or session-start check (until then the old 10 s cap stays).
- `wayfinder` is rewritten in orion's own words and loses its third-party licence credit, so the skill names no outside person or repository; it works as before, with the map's sections now called Settled and Fog (older maps are still read).
- The repo's own `CLAUDE.md` now asks, before any change to it, whether the change belongs in `BASE_CLAUDE.md` instead, so rules every project needs end up in the baseline.
- The planning skills (`wayfinder`, `harvest`, `harvest-qa`, `reconcile-issue-map`, `prd-to-tickets`) now follow the baseline: GitHub Issues only, the gate and a changelog line on every pull request, no branch switching in the main checkout.
- `dev-next` and `dev-quick` now follow the rules they ship with, so given-up stories can be picked up again, planning tickets and reconciles no longer raise false alarms, and the main checkout is never switched off its branch.
- BASE_CLAUDE.md lists every skill, drops the reply-length cap, allows a force-push only on the person's explicit word and bounds what starting a skill authorises, asks the person when their own rules contradict it; the repo's `CLAUDE.md` loses the contradictions the audit found.
- The installer is hardened from an audit: a failing or hanging auto-update at session start now says so, ends inside the hook's time limit and still exits 0 without leaving a temporary clone behind; settings edits survive a byte-order mark and count only real hooks; a Windows path as `--source` keeps `config.json` valid and a new `--source` on re-init is honoured; uninstall copes with a `CLAUDE.md` of only the import line and Windows line endings; the post-install question waits for `/orion-verify`; the hook and the branch scanner count branches the same way; no `__pycache__` is copied; the Windows launcher no longer closes the PowerShell window or leaves a temp folder. `tests/run.sh` now covers all of this on Ubuntu and on Windows, and CI rejects commits whose email is neither empty nor a GitHub no-reply address.
- The five PRDs for already shipped work (dev-quick, orion-verify, prd-to-tickets, reconcile-issue-map, the single rules file) are removed from `docs/PRDs/`: the skills and the baseline are the record now, so the folder no longer carries out-of-date plans.
- The orion repo's own `CLAUDE.md` drops a second round of repeats: the gate and definition of done, the harvest, QA, reconcile and issue-shape rules the imported `BASE_CLAUDE.md` already states, and three lines that said the same thing twice inside the file, so the skills' wiring is stated once as file names and couplings.
- The status line now shows the session or agent name (from `--agent`, `--name`, `/rename` or the AI title) so parallel sessions are told apart, and the pull-request segment is gone: it cost a `gh` call per branch and told nothing the session needed.
- New skill `clear-git-resources`: lists the stale worktrees, local and remote branches and leftover files in the worktree root in plain words, says what deleting each would lose, and deletes only what you agree to; the session-start hook offers it once the project has `branchLimit` branches (20 by default, in `.claude/orion/config.json`).
- The status line's git state now reads as words (`stashed:0 untracked:2 modified:5 unpushed:1`) instead of icons, so nothing on the line has to be remembered; the background-jobs flag is gone, as it never counted scheduled routines and earned its space poorly.
- The orion repo's own `CLAUDE.md` no longer repeats rules the imported `BASE_CLAUDE.md` already states (merge-on-green, GitHub Issues only, the harvest and QA thresholds, the drift probe, the parallel-planning rule), and its leak-scrub step no longer tells an agent to force-push, so one rule now has one home.
- BASE_CLAUDE.md now says a PRD is never created automatically: an agent stops and asks, drafts only on request, and the draft is the PRD only once the person approves it, so no big change gets ticketed or built on an unread PRD.
- The orion repo now runs on its own baseline: `CLAUDE.md` imports `baselines/BASE_CLAUDE.md` directly, so every edit to the baseline changes the repo's own rules in the same commit; CI runs the build, lint, typecheck and round-trip suite on every pull request so "merge on green" means something here too.
